3. DESIGN
==================================================

Das Design soll hochwertig, weich, bunt, verspielt und sehr angenehm wirken.

Es soll zur Atmosphäre von Wobbly Life passen, aber klar ein eigenes inoffizielles Fan-Design sein.

NICHT:

- offizielles RubberBandGames-HUD kopieren
- offizielles Logo imitieren
- originale UI-Grafiken 1:1 nachbauen
- so tun, als wäre die Seite offiziell

Stattdessen:
eine eigene hochwertige Companion-App mit ähnlicher verspielter Stimmung.

VISUELLE RICHTUNG:

- Himmelblau
- Türkis
- warmes Gelb
- Weiß
- dunkles Blau für Text
- Grün für erledigte Aufgaben
- Orange/Rot für Warnungen
- Violett für besondere Geheimnisse
- dezente Pastellfarben für Kategorien

UI:

- sehr runde Karten
- große Buttons
- weiche Schatten
- leichte plastische Tiefe
- dezente 3D-/Spielzeug-Optik
- große klare Typografie
- freundliche Icons
- klare Abstände
- kein langweiliges Tabellen-Layout
- kein Standard-Bootstrap-Look
- kein typisches Firmen-Dashboard

Die Seite soll sich wie ein Game-HUD bzw. eine hochwertige Gaming-Companion-App anfühlen.

Jeder Unlock braucht mindestens:

- Name Deutsch
- Name Englisch
- Beschreibung Deutsch

- Ort

- Event-only

- Tipps
- Bilder
- Kartenbild
- Kartenkoordinaten
- Kartenmarker
- Route
- verwandte Unlocks
- Quellen / interne Referenzen

Beispiel:

{
  "id": "ufo",
  "name": {
    "de": "UFO",
    "en": "UFO"
  },
  "category": "vehicle",
  "location": {
    "de": "Mountain Island",
    "en": "Mountain Island"
  },
  "mapPosition": {
    "x": 0.68,
    "y": 0.19
  },
  "difficulty": "medium",
  "guide": {
    "de": [],
    "en": []
  }
}

mapPosition möglichst NORMALISIERT speichern:

x: 0 bis 1
y: 0 bis 1

Die UI rendert alles dynamisch daraus.

11. EIGENE POSITION AUF DER KARTE
==================================================

Der Nutzer muss seine Position selbst markieren können.

Button:

DE:
„📍 Meine Position setzen“

EN:
„📍 Set my position“

Danach:

1. Nutzer klickt/tippt auf die Karte.
2. Dort erscheint sein Spieler-Marker.
3. Position wird lokal gespeichert.
4. Karte berechnet Entfernungen zu Zielen neu.

Spieler-Marker:

Am besten ein eigener kleiner, freundlicher Wobbly-artiger Kopf-Marker.

WICHTIG:
Nicht offiziellen Charakterkopf 1:1 kopieren.

Erstelle lieber einen eigenen Fan-Marker:

- gelber runder Kopf
- einfache Augen
- sehr reduzierte Form
- weißer Rand
- kleiner Pfeil darunter

Oder alternativ:
ein neutrales eigenes Spieler-Icon.

Marker darf leicht wobbeln/pulsieren.

18. ENTFERNUNGSBERECHNUNG
==================================================

Wenn die echte interne Spielentfernung nicht verfügbar ist:

NICHT so tun, als wäre es eine echte Meterangabe.

Stattdessen:

„ungefähre Kartenentfernung“

oder:

„ca. 620 Karteneinheiten“

Alternativ, wenn die Karte sinnvoll kalibriert werden kann:

Entfernung als geschätzte Ingame-Distanz.

Aber nur dann klar als:

„≈ geschätzt“

kennzeichnen.

Berechnung:

Spielerposition:
x1, y1

Ziel:
x2, y2

2D-Distanz:

sqrt(
  (x2 - x1)^2 +
  (y2 - y1)^2
)

Dann mit Kartenmaßstab skalieren.

==================================================
GERÄTE- UND DISPLAY-OPTIMIERUNG
==================================================

Die komplette Website/App muss für praktisch alle üblichen Bildschirmgrößen optimiert werden.

Unterstütze mindestens:

- kleine Smartphones
- normale Smartphones
- große Smartphones
- Smartphone Querformat
- Tablets Hochformat
- Tablets Querformat
- kleine Laptops
- normale Desktop-PCs
- große Desktop-Monitore
- Ultrawide-Monitore
- hochauflösende Displays / Retina / HiDPI
- Touch-Geräte
- Maus + Tastatur
- Windows-App-Fenster in frei veränderbarer Größe

Keine feste Auflösung voraussetzen.

Responsive Breakpoints nicht nur für „Mobile“ und „Desktop“ bauen, sondern Layout fließend anpassen.

WICHTIG:

Bei 320–400 px Breite:
- keine horizontalen Scrollbars
- keine abgeschnittenen Buttons
- Texte bleiben lesbar
- Bottom Navigation bleibt vollständig bedienbar
- Kartenmarker bleiben groß genug zum Antippen
- Guide-Karten passen auf den Bildschirm

Bei Tablets:
- nicht einfach die Smartphone-Version aufblasen
- 2-spaltige Layouts nutzen, wenn sinnvoll
- Karte größer darstellen
- Sidebar/Panel sinnvoll anordnen

Bei Desktop:
- verfügbare Fläche gut nutzen
- Inhalte nicht unnötig schmal in der Mitte einsperren
- sinnvolle Max-Width verwenden
- Dashboard kann mehrere Spalten nutzen

Bei Ultrawide:
- Inhalte nicht über die komplette Bildschirmbreite auseinanderziehen
- sinnvolle maximale Content-Breite
- zusätzliche Fläche für Karte, Filter oder Guide-Sidebar nutzen

Bei Querformat:
- Navigation und Kartenansicht sinnvoll neu anordnen
- wichtige Buttons dürfen nicht unterhalb des sichtbaren Bereichs verschwinden

Die interaktive Karte muss auf jedem Gerät funktionieren:

Desktop:
- Mausrad-Zoom
- Drag zum Verschieben
- Klick zum Setzen der Spielerposition
- Hover-Informationen zusätzlich zu Klick

Touch:
- Pinch-to-Zoom
- Drag/Pan
- Tippen zum Öffnen von Markern
- Tippen zum Setzen der Spielerposition
- keine Funktion darf Hover voraussetzen

Marker müssen groß genug sein, damit sie auf Touchscreens zuverlässig getroffen werden können.

Buttons und interaktive Elemente sollten auf Touch-Geräten mindestens ungefähr 44x44 CSS-Pixel große Trefferflächen besitzen.

Nutze:
- CSS Grid
- Flexbox
- clamp()
- min()
- max()
- responsive Typografie
- relative Größen
- sinnvolle Media Queries

Keine wichtigen Layout-Werte ausschließlich hart in Pixeln festlegen.

Bilder:
- responsive laden
- aspect-ratio verwenden
- object-fit sinnvoll einsetzen
- keine verzerrten Screenshots
- hochauflösende Displays berücksichtigen

Guide-Bilder und Karte dürfen auf kleinen Geräten vergrößert/gezoomt werden.

Modale Fenster:
- dürfen auf kleinen Geräten nicht über den Bildschirm hinausragen
- bei Bedarf als Fullscreen-Sheet auf Mobile anzeigen

Windows-App:
Das Layout muss auch funktionieren, wenn der Nutzer das Fenster:
- sehr klein macht
- maximiert
- auf einen zweiten Monitor verschiebt
- auf einem 4K-Monitor verwendet

Teste explizit ungefähr folgende Viewports:

320x568
360x800
390x844
430x932
768x1024
820x1180
1024x768
1280x720
1366x768
1440x900
1920x1080
2560x1440
3440x1440

Zusätzlich mindestens einen Mobile- und Tablet-Querformat-Test durchführen.

Es darf bei keiner unterstützten Größe:
- ungewolltes horizontales Scrollen geben
- überlappende UI geben
- abgeschnittene Texte geben
- unerreichbare Buttons geben
- unbedienbare Kartenmarker geben
